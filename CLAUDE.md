# ro-admin-ds — кит 2

Кодовая версия админского дизайн-кита: тема на токенах + компоненты на shadcn-vue + реестр,
из которого поштучно собираются страницы админки.

Источник визуала — **кит 1** в Figma. Интеграция с прод-фронтом — отдельная будущая задача,
в этой мы её не ждём и на неё не оглядываемся.

**Кит закрывает любой экран админки.** Ответа «такого компонента нет» не существует.

## Стек

Nuxt 4 · Tailwind v4 (CSS-first, `@theme`) · shadcn-vue поверх Reka UI.
Компоненты — в `app/components/ui`, токены — в `app/assets/css/tailwind.css`.

Дефолты shadcn-vue (`@/components/ui`, структура папок, нейминг файлов) — **штатные конвенции
кита 2**, не временная мера.

### Ловушка MCP: `get_metadata` врёт про страницы

`get_metadata` без `nodeId` возвращает **не все** страницы — только подгруженные. Для кита он
отдаёт 5 страниц из **38**, и среди этих пяти нет ни одной с мастер-компонентами.

На этом легко сделать ложный вывод, что компонентов в файле нет. Их там 100+.

- **Не полагаться** на этот список. Реальный перечень страниц и id мастер-компонентов —
  в `docs/kit-inventory.md`.
- `get_metadata` с `nodeId` дополнительно падает с ошибкой парсинга SSE на больших страницах
  (обрыв около 150 КБ).
- Надёжный способ обойти файл целиком — read-only скрипт через Plugin API
  (`figma.root.children`, `findAllWithCriteria`). Именно так снят инвентарь.
- `search_design_system` отдаёт имена и коллекцию, но **не значения**. Значения — только
  `get_variable_defs` по конкретному узлу либо чтением коллекции через Plugin API.

### Отсутствие и противоречие — разные вещи

| Ситуация | Что делаем |
|---|---|
| **Отсутствие** — компонента или состояния в ките просто нет | берём дефолт shadcn-vue **сразу**, заводим строку в `docs/design-debt.md` и метку `@debt` в шапке файла. Никогда не блокер, дизайнеров не ждём |
| **Противоречие** — конфликт с принятым решением, дубли с разным визуалом, совпадение палитры с семантикой | **всегда блокер**: в `docs/open-questions.md`, не решаем на месте |

Правило «визуал не изобретать» действует на противоречия. Отсутствие не останавливает работу
никогда: пустое место закрывается дефолтом и помечается долгом.

## Токены

Цвета, радиусы, шрифты, спейсинги — **только через токены**. Хардкод hex и px в компонентах
запрещён: `grep` по компонентам не должен находить значений вне файла токенов.

- **Цвет** переносится из Figma: коллекции `mode` (семантика) и `menu` (сайдбар).
- **Типографика, радиусы, спейсинги** — code-first: переменных в Figma нет, значения снимаются
  с фактических стилей компонентов.
- Коллекции `theme(primitives)` и `components` в Figma — легаси, **не использовать**. Имена вида
  `bg/dark_default`, `fg/white`, `brand/default`, `fg/semi_bright` относятся к ним.

Тема одна — светлая. Тёмная появится позже переопределением значений в `.dark`, а не вторым
набором имён — структуру закладываем под это.

Подробности, ловушки и мапинг-таблица: **`docs/tokens.md`**.

### Расширенная палитра

`status-01`..`status-06` в ките — **не статусы и не семантика**, а шесть дополнительных цветовых
рамп. Имя `status-*` в код не переносится: оно врёт о содержимом.

При сборке страниц дефолт — **семантические токены** (`accent`, `service/*`, `neutral`, `fg/*`,
`bg/*`, `border/*`). Расширенная палитра берётся **только по явному указанию** макета или
человека; «похоже по цвету» — не основание. Список легальных употреблений — в `docs/tokens.md`.

### Отчёт по мапингу токенов

Принимается по трём проверкам (полностью — в `docs/tokens.md`, раздел 9):

1. **двусторонняя полнота** — каждая переменная `mode`/`menu` либо замаплена, либо в списке
   «нет места»; каждый слот shadcn либо закрыт, либо в непокрытых;
2. **provenance на каждой строке** — `из файла` или `решение`;
3. **легаси не просочилось** — имён из коллекции `components` в отчёте нет.

## Нейминг

Правило «нейминг компонента в коде = нейминг в Figma» действует **на уровне вариантов**, не на
уровне файлов. Файлы и структура — по shadcn-vue.

- Значения `variant` — канонические shadcn там, где есть прямой аналог:
  `accent` → `default`, `txt` → `ghost`, `remove` → `destructive`.
  Кастомные значения — только там, где аналога нет.
- `variant` — это **стиль, а не место использования**. `btn_back`, `btn_map`, `page_btn`,
  `collapsed_btn` — не варианты Button, а композиции или части других компонентов
  (`page_btn` — внутренность Pagination). В проп их не сгребать.
- **Иконки** нормализуются: единый компонент `Icon`, имя без размера (`delete`, `search`, `copy`),
  размер — проп.
- **Лейбл** — опциональный слот внутри компонента. `*_title` из кита — это состояние
  «с подписью», а не отдельная сущность.
- Все соответствия «имя в ките 1 → имя в коде» фиксируются в мапинг-таблице `docs/tokens.md`.

## Правило порталов сайдбара

Сайдбар тёмный при светлом интерфейсе — это не тёмная тема и не второй мод.

Внутри контейнера сайдбара легальны **только** `sidebar-*`-токены и их расширения.
Всё, что вылетает из сайдбара порталом — dropdown, tooltip, popover — живёт на обычных светлых
токенах (`--popover` и компания). **Выпадающая плашка светлая даже из тёмного меню.**

## Витрина

Каждая волна заканчивается обновлением витрины, а не только кодом. Компоненты показываются в
состояниях: default, hover, focus, disabled, error.

Витрина читает токены прямо из таблиц стилей документа — добавили переменную в CSS, она сама
появилась на витрине. Дублировать список токенов руками не нужно.

### Метка долга

Компонент, стоящий на дефолте shadcn-vue, несёт в шапке файла метку `@debt` и строку в
`docs/design-debt.md`. Заводятся вместе: дефолт без метки делает долг невидимым.

```bash
grep -rn "@debt" app/components
```

## Окружение

Node лежит в `C:\Program Files\nodejs` и может отсутствовать в PATH дочерних процессов —
тогда PATH нужно подтянуть из машинных переменных перед запуском npm.

```bash
npm run dev
```

Dev-сервер поднимается на `http://localhost:3000`.
