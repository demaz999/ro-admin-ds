**Приоритет** (`scope.md`, «Источники и приоритет»; решение оркестратора 3, 2026-10-04). Вид и структура берутся из
макетов, поведение и тексты — из сводки. Где сводка молчит — берётся макет. Где макет и сводка расходятся — действует
сводка, расхождение пишется строкой раздела 11. `scope.md` главнее обоих. Пункты НС, которые меняют вид или поведение
страницы, — «Ждут людей» журнала: элемент собирается по более свежему источнику и помечается строкой реестра.

**Правило страницы** — по образцу правила 21 страницы схемы: вид компонентов — роли кита; роли нет — это нехватка, строка
раздела 11 и ось или карточка по лестнице.

**Как сняты числа.** Read-only скриптами Plugin API (`use_figma`) по кадрам и их поддеревьям: размеры — `absoluteBoundingBox`,
раскладка — `layoutMode`, `itemSpacing`, `padding*`, типографика — `fontSize`, `lineHeight`, `fontName.style`, переменные —
`boundVariables`, экземпляры — `getMainComponentAsync`, отрисовка — `absoluteRenderBounds`. Вид — `get_screenshot` каждого
кадра. `get_metadata` по секции `30824:1416` не вызывался: 40 105 × 1 760, 11 797 узлов. В Figma ничего не менялось.
Таблица прочитанных кадров — 12.2.

Ответ `use_figma` рвался на некоторых кадрах при любом размере возврата («Failed to parse SSE message»). Причина — служебные
символы в текстах макета: после замены управляющих символов, разделителей строк U+2028 и U+2029 и знаков вне BMP пробелом
те же кадры читаются целиком. Ловушка — в срезе такта 76 `handoff.md`.

Числа без узла вычислены, формула стоит рядом. Цвета в документ не переносятся значениями: вид идёт ролями кита, значения
макета остаются в Figma по node id.

**Макеты собраны из двух слоёв.** Кнопки (`btn_accent`, `btn_txt`, `btn_remove`, `btn_back`), поля `input`, `switch`,
`radiobtn_title`, `modal_cards_header`, иконки — экземпляры кита 1. Остальное — фреймы с именами `BaseMinimumCost`,
`TariffContextBanner`, `Container`, `Button`, `Input`; локальные компоненты дизайнера — секция «Компонентики» `30957:7808`.
Мастера у фреймов нет, источник вида — сам фрейм.

**Обезличивание** (scope, п. 8). В кадрах макета — имена пользователей, реальные суммы, идентификаторы и даты; в стенд и
этот документ они не переносятся. Стенд — один вымышленный сценарий: компания «Демо Страхование», группы КАСКО, ОСАГО,
«Недвижимость», обобщённые имена схем и типов объектов, круглые вымышленные цены.

### 6.3. Клиент и не клиент — §1, scope п. 7

Пара хранит два значения. Замок связи: связано — поле «Не клиент» повторяет «Клиент» и выключено; развязать — поле «Не
клиент» правится отдельно, значение остаётся прежним; связать снова — «Не клиент» принимает значение «Клиент». Новая пара
создаётся связанной (решение агента, стр. 51). Поля — целые неотрицательные, единица ₽; ввод — только цифры, разделитель
разрядов пробелом при показе; пустое поле — «не задано», ноль — допустимое значение (§11, НС п. 9).

### 6.4. Тарифные периоды — §8; машина состояний окон

**Период:** `{ id, status: 'current' | 'planned' | 'draft' | 'archive', from: 'ГГГГ-ММ', settings, pending }`. Интервал
начинается с 1-го числа месяца (§1, §8); `to` вычисляется — месяц перед `from` следующего в очереди. Текущий — тот, чей
интервал содержит «сегодня» (часы модели, оснастка `?now=`). Запланированные — в очереди после текущего. Черновик — без места
в очереди, с желаемой датой. Архив — прошедшие интервалы, только просмотр.

**Правки.** Любая правка не архивного периода автоматически пишется в его `pending` (§8): статус сохранения `saving → saved`
или `error` с «Повторить» (№ 7). Кнопки «Сохранить черновик» нет. Правки между вкладками не теряются. «Сохранить изменения»
активна, когда у выбранного периода есть `pending` (§11, стр. 40).

| Состояние | Событие | Условие | Переход |
|---|---|---|---|
| любой не архивный | правка | — | `pending` растёт, автосохранение |
| текущий | «Сохранить изменения» | за текущим нет запланированных | окно «Применить изменения?» (№ 48) |
| окно «Применить изменения?» | «Применить» | — | `settings := pending`, уведомление «Изменения применены» |
| окно «Применить изменения?» | «Оставить в черновике» | — | окно закрыто, `pending` остаётся |
| текущий или запланированный | «Сохранить изменения» | за ним в очереди есть запланированные | окно «Тариф находится в очереди» (№ 49), по умолчанию «Этот и все последующие» (§8, стр. 39) |
| окно очереди | «Сохранить изменения» | «Только к этому тарифу» | правки — только выбранному; метка «Изменяется» у него |
| окно очереди | «Сохранить изменения» | «Этот и все последующие» | правки — выбранному и всем после него; у последующих метка «Затронет» |
| список периодов | «Запланировать изменение цен» | — | окно «Планирование нового тарифа» (№ 44): месяц и год; прошедшие месяцы и текущий выключены |
| окно планирования | «Сохранить» | — | новый период `draft` с `from` = выбранный месяц, `settings` — копия текущего; переключатель — «Черновик с <месяц год>»; плашка черновика |
| черновик | «Сохранить изменения» | месяц свободен и позже текущего интервала… | черновик становится `planned`, уведомление «Тариф запланирован с <месяц год>» |
| черновик | «Сохранить изменения» | месяц входит в интервал текущего тарифа | окно «Дата занята действующим тарифом» (№ 50) |
| окно «Дата занята» | «Запланировать» | «Запланировать изменение» | черновик — `planned` с `from`; текущий действует до месяца перед ним |
| окно «Дата занята» | «Перезаписать» | «Перезаписать текущий тариф» | текущий завершается месяцем перед `from`; новый занимает его место в очереди; черновик не возвращается — метка «Необратимо» |
| черновик | «Сохранить изменения» | на этот месяц уже есть запланированный | окно «На эту дату уже запланирован тариф» (№ 51) |

| архив | правка | — | отказ: поля в «только чтении», «Сохранить изменения» не выводится (№ 47) |

Сводка описывает только выбор периода и «к выбранному и всем последующим» (§8); условия окон пересечений — по текстам макета
`31246:7271`: решение оркестратора 2026-10-04, стр. 43; вопрос аналитику — «Ждут людей» журнала. Граница «месяц входит в интервал текущего тарифа» и разница исходов

**Границы — как у `scheme-edit.md`, 6.2.** Модуль не знает DOM и компонентов. Отказы и подтверждения отдаёт очередью
уведомлений с текстами. Страница переводит модель в пропы, события компонентов — в операции. Панели группы и схемы пишут в
модель сразу (автосохранение §8; стр. 53).
