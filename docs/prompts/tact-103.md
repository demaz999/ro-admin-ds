# Встреча по дизайну 2026-08-20 — редактор схемы осмотра

Обезличенная выжимка обсуждения (00:09–00:50) из транскрипта владельца. Это направления проработки: окончательными решениями на встрече их не признали.

1. «Настройки» — одна колонка. Две колонки окончательно не запрещены, большинство против: блоки разной высоты при росте сдвигают соседей, на узком экране колонки перестраиваются, новичку труднее читать подряд.
2. Требование: привычное взаимное расположение блоков. Пользователи помнят настройки по положению границ блоков; рост одного блока не должен сдвигать соседние.
3. Правая часть — под внутреннюю навигацию по странице (оглавление, связанное с прокруткой) и под ИИ-помощника, который помогает настраивать схему; помощник сквозной на всю страницу (от себя комментарий, но тут речь идет о плагинах как claude для браузера, на самой странице их не будет, они по факту создают просто ещё одно окошко в браузере справа от страницы).
4. Навигацию справа будем использовать скорее всего как общий паттерн сразу на трёх страницах: настройки схемы, страница экспертизы (её второе меню слева переносится вправо, страницы ещё нет), «Мои осмотры» (фильтр справа). Вид — «островки», как фильтры списков: часть страницы, без второго сайдбара.
5. Панель ИИ в браузере пользователя открывается справа и забирает ширину — раскладка должна это выдерживать.
6. Поиск — самостоятельная часть задачи, по образцу настроек IDE: навигация сокращается до разделов с совпадениями, совпадения подсвечены, контекст страницы сохраняется; результат в закрытой группе или в боковой панели — сначала подсвечивается вход в неё, затем сам элемент.
