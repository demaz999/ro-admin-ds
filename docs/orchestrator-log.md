# Журнал оркестратора

Режим оркестратора — правило 24 `docs/chat-protocol.md`, роль — `docs/orchestrator.md`. Журнал ведёт оркестратор;
владелец читает его на приёмке глазом вместе с реестром расхождений `docs/scheme-edit.md`, раздел 11.

## Для владельца

### Маршрут приёмки

**Порядок приёмки (владелец, 2026-10-09).** Владелец идёт по странице в своём порядке и шлёт свои замечания пачками;
маршрут и пакеты ревью по пунктам не разбираются. Рекомендации маршрута и предложения ревью идут в такты только с ✓
владельца на доске.

1. На пачку — «Понял так»; у каждого номера сверка с находками ревью (К-, П-, Н-, Ф-, Ш-, В-, Р-, С-, Вс-, Т-), решениями
   цикла без владельца (маршрут, пункты 2, 5, 7; ревью 7.3) и строками реестра: «новое», «= К-3» (ревью предлагает то же)
   или «пересечение: К-3» (тот же элемент, ревью предлагает другое или больше).
2. «Новое» и «= …» — решения владельца: в такт по разделу 9, пункт 4.
3. «Пересечение» в такт не идёт: после «Понял так» — доска пачки, на каждое пересечение раздел выбора: A — владельца,
   B — ревью, C — сведённое, если есть; снимок текущего вида и вайрфреймы, код вариантов — по просьбе владельца. Такт по
   выбранному — после отметок владельца.
4. По слову «обход закончен» — итоговая доска из всего, чего замечания не коснулись: находки ревью «на решение» — карточки
   `ref` (title «К-3 · что», img — снимок текущего вида, href — стенд, take — предложение и цена, skip — что остаётся,
   suggest — рекомендация); решения цикла без владельца — разделы выбора «как собрано / альтернатива». В такты — только
   отмеченное. Вкусовые решения агентов (`scheme-edit.md`, 34.5) на доску не выносятся и остаются как собраны, пока их
   не задело замечание.
5. Статус находки ведётся в маршруте: «замечание N», «доска <id>», «мимо».
