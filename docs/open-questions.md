# Открытые вопросы

Живой документ. Пополняется по ходу волн. Правило из задания: визуал не изобретаем — любое
расхождение или сомнение попадает сюда, а не решается самостоятельно.

Статусы: 🔴 блокирует · 🟡 решено временно, нужна сверка · 🟢 закрыт

---

## 1. 🔴 В ките нет дизайн-токенов

**Факт.** В библиотеке `🖥️ UI Kit · Web Platform` не опубликовано ни одной variable и ни одного
style. Проверено через `search_design_system` с ограничением по `libraryKey` — по запросам цветов
и токенов возвращается пустой список и для variables, и для styles.

Для сравнения: у мобильных библиотек компании (`🎨 Color library · Mobile`, `📳 PWA · Рососмотр`)
переменные опубликованы и находятся поиском — то есть механика в компании работает, но веб-кит
ею не покрыт.

Косвенное подтверждение изнутри файла: на странице `➡️ slots` висит заметка дизайнера
«Нужно добавить дизайн-токены».

**Почему важно.** Пункт 2 волны 0 («вытянуть variables из Figma-кита через MCP») в исходном
виде невыполним. Работает запасное правило задания: взять значения из стилей компонентов,
внести в токены, зафиксировать вопрос.

**Что нужно от дизайнеров.** Один из вариантов:
- а) переменные в файле есть, но не опубликованы в библиотеку → опубликовать;
- б) переменных нет вовсе → подтвердить, что токены собираем мы, а кит потом равняется на них.

Пока не подтверждено — идём по варианту (б): выводим токены из фактических значений компонентов
и помечаем каждую догадку здесь.

## 2. 🟡 `get_variable_defs` недоступен удалённо

**Факт.** Инструмент возвращает `You currently have nothing selected` — он адресуется в десктопное
приложение Figma и требует выделенного слоя. Удалённо (по fileKey) работают `get_metadata`,
`get_screenshot`, `search_design_system`, `get_design_context`.

**Следствие.** Если по вопросу 1 окажется, что переменные в файле всё же есть, но не
опубликованы, — вытащить их можно будет либо после публикации, либо с открытым десктопным
Figma и ручным выделением слоя.

## 3. 🟡 Нейминг: кит против shadcn-vue

**Факт.** Кит именует компоненты в `snake_case` и дробит один UI-примитив на несколько
отдельных компонент-сетов. Только по запросу «Button» нашлись: `btn_accent`, `btn_secondary`,
`btn_outline`, `btn_txt`, `btn_back`, `btn_service`, `btn_remove`, `btn_map`, `accent_icon_btn`.

**Конфликт.** Правило задания «нейминг компонента в коде = нейминг компонента в Figma»
несовместимо с конвенцией shadcn-vue, где это один `Button` с пропом `variant`, лежащий в
`@/components/ui/button`. Буквальное следование правилу даст восемь несвязанных компонентов
вместо одного и сломает то, ради чего берётся shadcn-vue: модель знает его конвенции из обучения.

**Временное решение.** Один компонент `Button` по конвенции shadcn-vue; каждый `btn_*` из кита
становится значением пропа `variant` (`accent`, `secondary`, `outline`, `txt`, …). Соответствие
фиксируется в мапинг-таблице для будущего мержа с китом 3.

**Нужно решение.** Подтвердить трактовку правила: нейминг совпадает на уровне вариантов, а не
на уровне файлов компонентов.

## 4. 🟡 Версия Tailwind выбрана без сверки с китом 3

**Факт.** Доступа к прод-репо нет, версия Tailwind в ките 3 неизвестна — это открытый вопрос
самого задания.

**Временное решение.** Tailwind v4 (CSS-first, `@theme`). Причина: токены живут прямо в CSS как
нативные переменные, что точно ложится на задачу токен-ориентированного кита, и это текущая
версия shadcn-vue.

**Риск.** Если кит 3 на Tailwind v3 — придётся мигрировать слой утилит. Сами CSS-переменные
переносятся без изменений, то есть мержу по токенам это не мешает.

## 5. 🟡 Конвенции структуры проекта — дефолты shadcn-vue

**Факт.** По заданию: доступа к конвенциям кита 3 нет, используем дефолты shadcn-vue
(`@/components/ui`, структура папок, нейминг) и помечаем как временные.

**Нужно при появлении доступа.** Сверить: алиасы путей, расположение UI-компонентов, версия Nuxt,
версия Tailwind, соглашение об именах файлов.
