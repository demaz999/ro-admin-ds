# Запросы витрины к киту

Сюда конвейер 2 (Codex) пишет всё, что витрина не может решить сама: расхождение компонента с
`docs/naming.md` или с макетом, недостающий проп, слот или состояние. Витрина правила не
устанавливает и кит не правит — запрос закрывает конвейер 1 (Claude Code) своим тактом.

Сюда же конвейер 1 пишет строку, когда меняет API компонента и механически правит примеры на
витрине: «API <компонент> изменён, примеры поправлены механически, оформление — Codex».

Статусы: `открыт` · `в такте N` · `закрыт` · `отклонён` (с причиной).

| ID | Дата | Что нужно | Зачем | Статус |
|---|---|---|---|---|
| SHOWCASE-INPUT-001 | 2026-09-15 | Специальное поле с маской или штатная интеграция Input с маской | Не подменять формат и ограничения плейсхолдером; правило переноса подтверждено владельцем | открыт |
| SHOWCASE-INPUT-002 | 2026-09-15 | Выровнять левую подпись Field по базовой линии текста Input | Сейчас Field центрирует подпись по высоте контрола; перенос выравнивания по базовой линии подтверждён владельцем | открыт |
| SHOWCASE-INPUT-003 | 2026-09-15 | Связь Field label с нативным input и передача id/name/autocomplete и других штатных атрибутов | Доступное и корректно автозаполняемое поле; текущая обвязка не знает id внутреннего input | открыт |
| SHOWCASE-INPUT-004 | 2026-09-15 | После очистки гарантированно возвращать фокус в нативный input | Позволяет сразу ввести новое значение; текущий clearable только очищает model | открыт |
