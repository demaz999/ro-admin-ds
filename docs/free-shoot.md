# Распределение свободной съёмки (VA-9265): три составных компонента

Такт 30, часть 1 — разбор, 2026-09-23. Кода нет: стоп-точка перед сборкой. Срочная задача владельца
для фронтенда: компоненты забираются с витрины кита в сторибук фронтов, поэтому API и полнота
состояний здесь важнее обычного.

## Источники

| Что | Файл | Роль в разборе |
|---|---|---|
| интерактивный прототип v17 | [sources/va-9265/va-9265-v17.html](sources/va-9265/va-9265-v17.html) | состав, геометрия, состояния — **единственный визуальный источник** |
| дизайн-спецификация, редакция 1 | [sources/va-9265/spec-va9265.html](sources/va-9265/spec-va9265.html) | состояния, права, тексты — ссылки вида §4, §5.1 |

**Мастеров в Figma у этих компонентов нет.** Провенанс значения записывается как «прототип v17,
`<селектор>`» либо «спека §N». Прототип свёрстан в своей стилистике: его цвета, радиусы и кегли
переводятся на токены и роли кита по смыслу (таблицы «Токены» в разделе каждого компонента).
Наложения на `/compare` не будет: эталона-мастера нет, сверка — с прототипом.

**Как сняты числа.** Headless Chrome через DevTools Protocol, окно 1440×900, прототип открыт как
файл. Состояния выставлены функциями самого прототипа: `applyScenario('review' | 'mixed' | 'empty')`
(это кнопки «Состояние осмотра» стартового окна), `createObject`, `runWand('full')`; где нужного
сочетания в демоданных нет — полям кадра `objId` / `stepId` / `lock` / `auto` присвоены значения
напрямую, после чего вызван родной `render()`. Геометрия — `getBoundingClientRect`, цвет и кегль —
`getComputedStyle`. Наведение — курсором через `Input.dispatchMouseEvent`, как у живого
пользователя. Скриншоты — 2x, по node-элементу состояния.

> **Шрифт прототипа — не свидетель.** В стеке прототипа первым стоит `PT Root UI`, но гарнитура
> не подключена: браузер рисует запасной шрифт. Кегли и начертания взяты из computed-значений, а
> гарнитура в коде — наша тема.

## 1. Плитка кадра — `FrameTile`

Плитка ленты материалов (§8). Кадр — фотография или видео (§2). Заметки полосами (§8.4) в
компонент **не входят**: у них своя анатомия, и в задачу такта они не заказаны.

### 1.5. Черновик API

```ts
// app/components/ui/frame-tile/FrameTile.vue
defineProps<{
  src: string
  alt?: string
  kind?: 'photo' | 'video'          // видео — длительность в подписи
  duration?: string                  // «0:36»
  time: string                       // «09:57», подпись свободного кадра
  size?: 'md' | 'lg'                 // 176 / 272 — минимум колонки, ширину даёт сетка
  state?: 'free' | 'assigned' | 'suggested' | 'locked' | 'rejected'
  stepName?: string                  // в плашке; обязателен при state ≠ free
  locateHint?: string                // «Пропиточная линия · Шильдик» — вторая строка подсказки
  lockReason?: string                // «Кадр в проверенном шаге» — у locked и rejected
  selected?: boolean
  selectionMode?: boolean            // флажок виден без наведения
  dimmed?: boolean                   // §15.2
  linked?: boolean                   // §15.2, пара к dimmed
  dragging?: boolean
}>()
defineEmits<{
  'toggle-select': [event: MouseEvent]   // клик по плитке; Shift страница читает из event
  open: []                               // иконка открытия, §8.3
  locate: []                             // название шага или лупа, §15.3
  unassign: []                           // крестик
}>()
```

Собирается из: `Image ratio="4:3"` (или `MediaGalleryItem` — **решение 2**), `Checkbox on-image`,
`IconButton`, `Icon` (`check`, `refresh`, `search`, `close`, `lock`, `play`, `fullscreen` — новый),
`Tooltip`. Перетаскивание — атрибут `draggable` страница ставит сама; компонент не слушает
`dragstart`.

**Доступность** приходит с данными.

| Состояние | Условие | Вид | Скриншот |
|---|---|---|---|

**§5.1 выполняется прототипом:** замороженный — серая заливка, замок с датой, нейтральный счётчик,
нет номера; заполненный — прозрачность 0.6, зелёный счётчик и «· заполнен». Общего визуального
средства у них нет.

**§5.3 — где замечание.** Спека: «рядом с названием, без раскрытия по клику». Прототип: отдельной
строкой под требованием, без раскрытия. Условие «без клика» выполнено, «рядом» — нестрого; при
длинном замечании строка переносится (замер: 29.7 на двух строках, [step-redo](free-shoot-step-redo.png)).
Переносим как в прототипе — отдельного решения не требует.

### 2.3. Пересечение осей

✓ — сочетание допустимо и различимо; ◐ — допустимо, но одна ось визуально подавлена; ✗ — невозможно.

| наполненность ↓ / доступность → | открыт | заполнен по лимиту | заморожен | повторить |
|---|---|---|---|---|
| пусто, обязательный | ✓ | ✗ | ◐ наполненность не видна: счётчик нейтральный, слоты скрыты | ✓ типичный случай: отклонённые не считаются ([step-redo](free-shoot-step-redo.png)) |
| пусто, необязательный | ✓ | ✗ | ◐ | ✓ |
| недобор | ✓ | ✗ | ◐ | ✓ |
| норма | ✓ | ✗ | ◐ ([step-frozen-from-step](free-shoot-step-frozen-from-step.png): «3 / от 2») | ✓ пересняли, вердикт снимается только в Core |
| заполнен | ✗ — это и есть «заполнен по лимиту» | ✓ | ◐ заморожен побеждает: §5.1 | ✓ жёлтая рамка + прозрачность 0.6 |
| переполнен | ✓ | ✓ в прототипе оба сразу — **решение 5** | ◐ | ✓ |

«Заполнен» на оси наполненности и «заполнен по лимиту» на оси доступности — **одно условие**
(`N = max`, §5 обе таблицы). В коде это одно вычисление и ни одного пропа.

### 3.3. Сверка с долгом `Progress`

**Факт:** в `design-debt.md` `Progress` записан как «целиком дефолт shadcn-vue», но **компонента в
коде нет** — ни в `app/components/ui`, ни импортом где-либо. Строка реестра описывает дыру:

закрывается **частично**: компонент появляется, но источник визуала — прототип VA-9265; мастера в ките 1 по-прежнему нет.
Строка в `design-debt.md` меняет вид с «дефолт shadcn» на «собран по прототипу, мастера в ките нет».

### 3.5. Черновик API

```ts
// app/components/ui/progress/Progress.vue
defineProps<{
  value: number          // всё сделанное, включая чужое
  max?: number           // по умолчанию 100
  locked?: number        // чужая доля, от начала, поверх value
}>()                     // value === max → состояние «готово»; role="progressbar", aria-valuenow

// app/components/ui/progress/ProgressStat.vue
defineProps<{
  label: string          // «Кадры разложены»
  value: string          // «14 из 196» — формулирует страница
  progress?: { value: number; max: number; locked?: number }   // нет — нет полосы («Объекты»)
  sub?: string           // «6 привязано до вас»; пусто — строки нет
}>()
```

`ProgressStat` своих текстов **не выводит**: подписи и значения формулирует страница — это
агрегаты по всему осмотру. Ключи §18 для страницы: `stat.frames.sub` «<N> привязано до вас»,
`stat.steps.sub` «<N> закрыто проверкой». Прототипные значения без ключа в §18: «N из M закрыто»,
«обязательных нет», «N зданий · N единиц», «N объектов проверено».

## 5. Решения — стоп-точка

**Решений владельцу: 8.** Ещё 9 развилок закрыты фактом или правилом кита — таблица ниже.

### Закрыто фактом или правилом

| Развилка | Факт | Итог |
|---|---|---|
| промежуток ленты 9 или 16 | число колонок одинаково: 5 M и 3 L при 1440, 4 M при 1280 | 16 (`MediaGallery` md) |
| размер L = 272 | ширина варианта `16:10` мастера `Image` `174:3128` | 272 остаётся |
| флажок выделения на плитке | правило «Контрол поверх изображения», `Checkbox on-image` | `Checkbox on-image` |
| иконка открытия | то же правило | `IconButton sm elevated` + `shadow-on-image`, глиф `fullscreen` |
| приглушение 32% (§15.2) | 0.32 — уже ступень кита, `--opacity-disabled-strong` (спека `Button` `45:175`) | новая роль `--opacity-dimmed` со значением существующей ступени |
| длительность видео красным | «цвет по роли» — длительность не ошибка | `--foreground-secondary` + глиф `play` |
| крестик миниатюры на красном | «цвет по роли» — открепление обратимо (§10.6) | `--scrim-dark` + белый крестик |
| подпись счётчика прописными | прописных в `app/components/ui` нет ни одной | строчные `text-2xs` |
| фиолетовая полоса окна автораспределения | расширенная палитра только по явному указанию | `--primary` |

Допущение прототипа помечено, но решения не требует: **перечёркнутые отклонённые кадры в шаге**
(§4.2) — допущение §20.5, вопрос к Core. Компонент несёт `StepThumb state="rejected"`; если Core
выберет «возврат в ленту», состояние просто перестанет приходить.

### Решение 1 — имена и раскладка по папкам

- **Рекомендация:** `FrameTile` (`ui/frame-tile/`), `StepRow` + `StepThumb` (`ui/step-row/`),
  `Progress` + `ProgressStat` (`ui/progress/`). «Кадр», «шаг» — термины спеки §2, которые читаются
  без пояснений; `Progress` — каноническое имя shadcn, а `ProgressStat` — его обвязка.
- Цена: `FrameTile` не говорит о медиа как таковом — для галереи без распределения пришлось бы
  брать `MediaGalleryItem`, и две плитки жили бы рядом.
- Альтернатива `MediaTile` / `StructureStep` / `StatMeter`: имена шире задачи, но слово «структура»
  спека резервирует за панелью, а `StatMeter` не опознаётся как прогресс.

### Решение 2 — основа плитки: 4:3 или `MediaGalleryItem` 16:10

- **Рекомендация: своя плитка на `Image ratio="4:3"`**, радиус и подложка — ступени `MediaGalleryItem`
  md (16, `--muted`), подпись и накладные части — свои.
- Цена: плитка кадра и плитка галереи кита выглядят по-разному в пропорции; `MediaGalleryItem`
  остаётся без потребителя в этой задаче.
- Альтернатива «`MediaGalleryItem` как есть, 16:10»: у кадров с телефона срезается 16.7% высоты — у
  эксперта, который ищет на кадре шильдик или номер, это рабочая потеря. Плюс ось пропорции в
  перенесённом мастере — расширение матрицы мастера, которое по протоколу пишется строкой в
  `waves.md`.
- Альтернатива «как в прототипе, радиус 6 и рамка»: у кита для медиа радиус 16/24/8 по ступеням
  `MediaGalleryItem`; 6 — ступень малой кнопки (`57:343`), к плитке её не привязать.
- Сопутствующее, решается вместе: **время и длительность под плашкой.** В прототипе плашка
  перекрывает строку подписи — у распределённого видео не видна длительность. Рекомендация: оставить
  как в прототипе (§4 требует время только у свободного); альтернатива — поднять плашку над подписью
  и растить плитку на 25px в состояниях с привязкой.

### Решение 3 — тёмная ступень служебных цветов: плашки и текст на мягких заливках

**Факт:** белый текст ни на одной служебной роли кита не дотягивает до 4.5:1 — `--success` 2.7,
`--success-pressed` 3.7, `--warning` 2.7, `--warning-pressed` 3.5, `--destructive` 3.7,
`--destructive-pressed` 4.35. Цветной текст на своей мягкой заливке — тоже: `--warning` на
`--warning-surface` 2.4, `--success` на `--success-surface` 2.5. Прототип держит контраст тёмными
ступенями, которых в ките нет: зелёная плашка 8.2, охристая 5.9, красная 7.5, тёмно-охристый текст
на мягкой заливке 5.4.

- **Рекомендация: завести три роли `--success-strong`, `--warning-strong`, `--destructive-strong`** со
  значениями прототипа (`#145a37`, `#8c5a0b`, `#96322e`), провенанс «прототип v17», и запрос
  дизайнерам в `figma-fixes.md` завести ступень в коллекции `mode`. Роли закрывают плашки плитки,
  текст «не хватает», строку «Повторить», «· заполнен» и текст счётчиков-пилюль.
- Цена: три значения не из кита 1 — до ответа дизайнеров они живут с провенансом прототипа.
- Альтернатива «одна тёмная плашка `--scrim-dark` на все состояния, цвет несёт только ведущий
  глиф»: прецедент есть (`NavigationTile`), новых ролей нет. Но спека §4 требует «зелёную»,
  «охристую», «серую», «красную» плашки — это отклонение от спеки в `figma-fixes.md`, и текст на
  мягких заливках остаётся нечитаемым.
- Альтернатива «ближайшие существующие: `*-pressed`»: ни одна не проходит 4.5:1 для текста 12px.

### Решение 4 — счётчик-пилюля шага

Прототип: высота 18, 11/16 700, мягкие заливки (`*-surface`) с цветным текстом, пять тонов:
нейтральный, красный, жёлтый, зелёный, серый у замороженного.

- **Рекомендация: своя часть внутри `StepRow`** — геометрия `Badge sm` (высота 16, паддинг 8,
  радиус полный), текст `text-2xs` 12/16 bold, тона на `*-surface` + `*-strong` (решение 3).
- Цена: вторая пилюля в ките рядом с `Badge`; при появлении третьего потребителя её стоит вынести.
- Альтернатива «вариант `soft` у `Badge`»: `Badge` перенесён с мастера Атома `913:8279` с матрицей
  6×2; мягких тонов в мастере нет, и расширение матрицы перенесённого компонента — против правила
  «число вариантов в коде = числу вариантов в мастере».
- Альтернатива «`Badge sm` залитый как есть»: 10/12 на насыщенной заливке с белым текстом — те же
  2.7:1 из решения 3, и строка шага начинает кричать там, где прототип говорит тихо.

### Решение 5 — переполненный шаг: прототип против спеки (вопрос 36)

**Противоречие.** Спека §5: «переполнен — красный счётчик, красная рамка строки», «заполнен —
помета „· заполнен“, строка приглушена». Прототип считает заполненность как `N ≥ max`, поэтому
переполненный шаг получает **оба** вида: красную рамку, «· заполнен» и прозрачность 0.6
([step-over](free-shoot-step-over.png)). Красный на 60% бледнеет — ошибка читается слабее нормы.
Строка причины `.why` в разметке есть, но не заполняется нигде.

- **Рекомендация: переполнен побеждает** — красная рамка и счётчик, без «· заполнен» и без
  прозрачности; приём по-прежнему отклоняется. Это буква спеки §5.
- Цена: расходимся с прототипом, на который смотрят фронты.
- Альтернатива «как в прототипе»: сочетание двух сигналов с противоположным смыслом («готово» и
  «ошибка») в одной строке.

Записано вопросом 36 в `open-questions.md`: противоречие источников — блокер по правилу кита, решается
владельцем.

### Решение 6 — `Progress` компонентом кита

- **Рекомендация:** собрать `Progress` (дорожка, своя доля, чужая доля, «готово») и `ProgressStat`
  на нём; окно автораспределения §12.5 берёт голый `Progress`. Строка долга `Progress` закрывается
  частично — см. 3.3.
- Цена: первый прогресс кита рождается из прототипа одной задачи; если дизайнеры потом нарисуют
  свой, придётся мигрировать.
- Альтернатива «полоса внутри `ProgressStat`, `Progress` не заводить»: окно автораспределения
  соберёт вторую полосу рядом, и в ките будут две реализации одного.

### Решение 7 — кто держит вспышку 1.5 с (§15.3)

- **Рекомендация: компонент.** Проп `flash` — число; смена значения запускает анимацию 1.5 с,
  компонент сам её завершает и сам уважает `prefers-reduced-motion`. Страница только выдаёт новое
  значение (например, `Date.now()`).
- Цена: проп-«спусковой крючок» вместо булева — непривычный API.
- Альтернатива «булев `flash`, страница снимает через таймер» (как в прототипе: класс ставится и
  снимается через 1600 мс): длительность живёт на странице, у каждого потребителя своя, и повторная
  вспышка на том же шаге требует выключить-включить проп.

### Решение 8 — больше восьми миниатюр

Прототип обрезает содержимое шага до 8 (`slice(0,8)`) **без индикации** — девятый кадр в шаге не
виден никак. Спека §9.6: «до 8 штук». В CSS прототипа заготовлен неиспользуемый класс `.slots .plus`
(10.5 `#8A9AAB`).

- **Рекомендация: хвост «+N»** после восьмой миниатюры, `text-2xs` `--muted-foreground`, клик —
  событие `more` (страница решает, что показать: полноэкранный просмотр с первого скрытого).
- Цена: новый элемент, которого в прототипе нет в отрисовке.
- Альтернатива «как в прототипе»: у шага «Общий вид» без максимума кадров может быть 20 — строка
  врёт о содержимом, счётчик говорит 20, миниатюр 8.

### Замечено при сборке

- **Пилюля сливается со строкой своего тона.** У «переполнен» строка и пилюля на
  `--destructive-surface`, у «Повторить» с недобором — на `--warning-surface`: пилюля читается только
  текстом. В прототипе так же у переполненного (строка и пилюля на `#FBEBEA`). Цвет текста `*-strong`
  держит контраст, поэтому на стенде это не дефект; при мастере пилюли стоит решить, нужна ли ей
  обводка на тонированной строке.
- **Рамка «Повторить» заметно плотнее прототипа**: `--warning` вместо бледного `#E7C77A` — по таблице
  токенов разбора (2.5), роль «нужно внимание»; `--warning-disabled` ближе по цвету, но несёт роль
  «выключено».
