# Распределение свободной съёмки (VA-9265): три составных компонента

Такт 30, часть 1 — разбор, 2026-09-23. Кода нет: стоп-точка перед сборкой. Срочная задача владельца
для фронтенда: компоненты забираются с витрины кита в сторибук фронтов, поэтому API и полнота
состояний здесь важнее обычного.

**Прототип в репозитории — обезличенная копия**, решение владельца 2026-09-23; замеры части 1 сняты
с исходной версии `c8aa1a0`, геометрия и стили в копии не менялись. В копии встроенные кадры
(208 превью, 200×150 и четыре 150×200) заменены однотонными заглушками `#DEE5ED` той же пропорции,
имя клиента → «Демо-осмотр»; логика, разметка, CSS и остальные тексты те же. «VIEWAPP» — название продукта, обезличивания не требует (решение владельца 2026-09-23, довесок такта 31).
Скриншоты `free-shoot-*.png` и пары `free-shoot-pair-*.png` пересняты с копии под прежними именами.

**Мастеров в Figma у этих компонентов нет.** Провенанс значения записывается как «прототип v17,
`<селектор>`» либо «спека §N». Прототип свёрстан в своей стилистике: его цвета, радиусы и кегли
переводятся на токены и роли кита по смыслу (таблицы «Токены» в разделе каждого компонента).
Наложения на `/compare` не будет: эталона-мастера нет, сверка — с прототипом.

**Как сняты числа.** Headless Chrome через DevTools Protocol, окно 1440×900, прототип открыт как
файл. Состояния выставлены функциями самого прототипа: `applyScenario('review' | 'mixed' | 'empty')`
(это кнопки «Состояние осмотра» стартового окна), `createObject`, `runWand('full')`; где нужного
сочетания в демоданных нет — полям кадра `objId` / `stepId` / `lock` / `auto` присвоены значения
напрямую, после чего вызван родной `render()`. Геометрия — `getBoundingClientRect`, цвет и кегль —
`getComputedStyle`. Наведение — курсором через `Input.dispatchMouseEvent`, как у живого
пользователя. Скриншоты — 2x, по node-элементу состояния.

> **Шрифт прототипа — не свидетель.** В стеке прототипа первым стоит `PT Root UI`, но гарнитура
> не подключена: браузер рисует запасной шрифт. Кегли и начертания взяты из computed-значений, а
> гарнитура в коде — наша тема.

### 1.5. Черновик API

```ts
// app/components/ui/frame-tile/FrameTile.vue
defineProps<{
  src: string
  alt?: string
  kind?: 'photo' | 'video'          // видео — длительность в подписи
  duration?: string                  // «0:36»
  time: string                       // «09:57», подпись свободного кадра
  size?: 'md' | 'lg'                 // 176 / 272 — минимум колонки, ширину даёт сетка
  state?: 'free' | 'assigned' | 'suggested' | 'locked' | 'rejected'
  stepName?: string                  // в плашке; обязателен при state ≠ free
  locateHint?: string                // «Пропиточная линия · Шильдик» — вторая строка подсказки
  lockReason?: string                // «Кадр в проверенном шаге» — у locked и rejected
  selected?: boolean
  selectionMode?: boolean            // флажок виден без наведения
  dimmed?: boolean                   // §15.2
  linked?: boolean                   // §15.2, пара к dimmed
  dragging?: boolean
}>()
defineEmits<{
  'toggle-select': [event: MouseEvent]   // клик по плитке; Shift страница читает из event
  open: []                               // иконка открытия, §8.3
  locate: []                             // название шага или лупа, §15.3
  unassign: []                           // крестик
}>()
```

Собирается из: `Image ratio="4:3"` (или `MediaGalleryItem` — **решение 2**), `Checkbox on-image`,
`IconButton`, `Icon` (`check`, `refresh`, `search`, `close`, `lock`, `play`, `fullscreen` — новый),
`Tooltip`. Перетаскивание — атрибут `draggable` страница ставит сама; компонент не слушает
`dragstart`.

|---|---|---|---|

**§5.1 выполняется прототипом:** замороженный — серая заливка, замок с датой, нейтральный счётчик,
нет номера; заполненный — прозрачность 0.6, зелёный счётчик и «· заполнен». Общего визуального
средства у них нет.

**§5.3 — где замечание.** Спека: «рядом с названием, без раскрытия по клику». Прототип: отдельной
строкой под требованием, без раскрытия. Условие «без клика» выполнено, «рядом» — нестрого; при
длинном замечании строка переносится (замер: 29.7 на двух строках, [step-redo](free-shoot-step-redo.png)).
Переносим как в прототипе — отдельного решения не требует.

### 2.3. Пересечение осей

✓ — сочетание допустимо и различимо; ◐ — допустимо, но одна ось визуально подавлена; ✗ — невозможно.

| наполненность ↓ / доступность → | открыт | заполнен по лимиту | заморожен | повторить |
|---|---|---|---|---|
| пусто, обязательный | ✓ | ✗ | ◐ наполненность не видна: счётчик нейтральный, слоты скрыты | ✓ типичный случай: отклонённые не считаются ([step-redo](free-shoot-step-redo.png)) |
| пусто, необязательный | ✓ | ✗ | ◐ | ✓ |
| недобор | ✓ | ✗ | ◐ | ✓ |
| норма | ✓ | ✗ | ◐ ([step-frozen-from-step](free-shoot-step-frozen-from-step.png): «3 / от 2») | ✓ пересняли, вердикт снимается только в Core |
| заполнен | ✗ — это и есть «заполнен по лимиту» | ✓ | ◐ заморожен побеждает: §5.1 | ✓ жёлтая рамка + прозрачность 0.6 |
| переполнен | ✓ | ✓ в прототипе оба сразу — **решение 5** | ◐ | ✓ |

«Заполнен» на оси наполненности и «заполнен по лимиту» на оси доступности — **одно условие**
(`N = max`, §5 обе таблицы). В коде это одно вычисление и ни одного пропа.

### 3.3. Сверка с долгом `Progress`

**Факт:** в `design-debt.md` `Progress` записан как «целиком дефолт shadcn-vue», но **компонента в
коде нет** — ни в `app/components/ui`, ни импортом где-либо. Строка реестра описывает дыру:
собранного дефолта нет. Первым детерминированным прогрессом кита станет полоса этого такта.

необязательная чужая доля, состояние «готово». `ProgressStat` компонует `Progress` с подписью,
значением и подписью под полосой; окно автораспределения берёт `Progress` без обвязки. Долг
закрывается **частично**: компонент появляется, но источник визуала — прототип VA-9265; мастера в ките 1 по-прежнему нет.
Строка в `design-debt.md` меняет вид с «дефолт shadcn» на «собран по прототипу, мастера в ките нет».

### 3.5. Черновик API

```ts
// app/components/ui/progress/Progress.vue
defineProps<{
  value: number          // всё сделанное, включая чужое
  max?: number           // по умолчанию 100
  locked?: number        // чужая доля, от начала, поверх value
}>()                     // value === max → состояние «готово»; role="progressbar", aria-valuenow

// app/components/ui/progress/ProgressStat.vue
defineProps<{
  label: string          // «Кадры разложены»
  value: string          // «14 из 196» — формулирует страница
  progress?: { value: number; max: number; locked?: number }   // нет — нет полосы («Объекты»)
  sub?: string           // «6 привязано до вас»; пусто — строки нет
}>()
```

`ProgressStat` своих текстов **не выводит**: подписи и значения формулирует страница — это
агрегаты по всему осмотру. Ключи §18 для страницы: `stat.frames.sub` «<N> привязано до вас»,
`stat.steps.sub` «<N> закрыто проверкой». Прототипные значения без ключа в §18: «N из M закрыто»,
«обязательных нет», «N зданий · N единиц», «N объектов проверено».

## 5. Решения — стоп-точка

**Решений владельцу: 8.** Ещё 9 развилок закрыты фактом или правилом кита — таблица ниже.

### Закрыто фактом или правилом

| Развилка | Факт | Итог |
|---|---|---|
| промежуток ленты 9 или 16 | число колонок одинаково: 5 M и 3 L при 1440, 4 M при 1280 | 16 (`MediaGallery` md) |
| размер L = 272 | ширина варианта `16:10` мастера `Image` `174:3128` | 272 остаётся |
| флажок выделения на плитке | правило «Контрол поверх изображения», `Checkbox on-image` | `Checkbox on-image` |
| иконка открытия | то же правило | `IconButton sm elevated` + `shadow-on-image`, глиф `fullscreen` |
| приглушение 32% (§15.2) | 0.32 — уже ступень кита, `--opacity-disabled-strong` (спека `Button` `45:175`) | новая роль `--opacity-dimmed` со значением существующей ступени |
| длительность видео красным | «цвет по роли» — длительность не ошибка | `--foreground-secondary` + глиф `play` |
| крестик миниатюры на красном | «цвет по роли» — открепление обратимо (§10.6) | `--scrim-dark` + белый крестик |
| подпись счётчика прописными | прописных в `app/components/ui` нет ни одной | строчные `text-2xs` |
| фиолетовая полоса окна автораспределения | расширенная палитра только по явному указанию | `--primary` |

Допущение прототипа помечено, но решения не требует: **перечёркнутые отклонённые кадры в шаге**
(§4.2) — допущение §20.5, вопрос к Core. Компонент несёт `StepThumb state="rejected"`; если Core
выберет «возврат в ленту», состояние просто перестанет приходить.

### Решение 1 — имена и раскладка по папкам

- **Рекомендация:** `FrameTile` (`ui/frame-tile/`), `StepRow` + `StepThumb` (`ui/step-row/`),
  `Progress` + `ProgressStat` (`ui/progress/`). «Кадр», «шаг» — термины спеки §2, которые читаются
  без пояснений; `Progress` — каноническое имя shadcn, а `ProgressStat` — его обвязка.
- Цена: `FrameTile` не говорит о медиа как таковом — для галереи без распределения пришлось бы
  брать `MediaGalleryItem`, и две плитки жили бы рядом.
- Альтернатива `MediaTile` / `StructureStep` / `StatMeter`: имена шире задачи, но слово «структура»
  спека резервирует за панелью, а `StatMeter` не опознаётся как прогресс.

### Решение 2 — основа плитки: 4:3 или `MediaGalleryItem` 16:10

- **Рекомендация: своя плитка на `Image ratio="4:3"`**, радиус и подложка — ступени `MediaGalleryItem`
  md (16, `--muted`), подпись и накладные части — свои.
- Цена: плитка кадра и плитка галереи кита выглядят по-разному в пропорции; `MediaGalleryItem`
  остаётся без потребителя в этой задаче.
- Альтернатива «`MediaGalleryItem` как есть, 16:10»: у кадров с телефона срезается 16.7% высоты — у
  эксперта, который ищет на кадре шильдик или номер, это рабочая потеря. Плюс ось пропорции в
  перенесённом мастере — расширение матрицы мастера, которое по протоколу пишется строкой в
  `waves.md`.
- Альтернатива «как в прототипе, радиус 6 и рамка»: у кита для медиа радиус 16/24/8 по ступеням
  `MediaGalleryItem`; 6 — ступень малой кнопки (`57:343`), к плитке её не привязать.
- Сопутствующее, решается вместе: **время и длительность под плашкой.** В прототипе плашка
  перекрывает строку подписи — у распределённого видео не видна длительность. Рекомендация: оставить
  как в прототипе (§4 требует время только у свободного); альтернатива — поднять плашку над подписью
  и растить плитку на 25px в состояниях с привязкой.

### Решение 3 — тёмная ступень служебных цветов: плашки и текст на мягких заливках

**Факт:** белый текст ни на одной служебной роли кита не дотягивает до 4.5:1 — `--success` 2.7,
`--success-pressed` 3.7, `--warning` 2.7, `--warning-pressed` 3.5, `--destructive` 3.7,
`--destructive-pressed` 4.35. Цветной текст на своей мягкой заливке — тоже: `--warning` на
`--warning-surface` 2.4, `--success` на `--success-surface` 2.5. Прототип держит контраст тёмными
ступенями, которых в ките нет: зелёная плашка 8.2, охристая 5.9, красная 7.5, тёмно-охристый текст
на мягкой заливке 5.4.

- **Рекомендация: завести три роли `--success-strong`, `--warning-strong`, `--destructive-strong`** со
  значениями прототипа (`#145a37`, `#8c5a0b`, `#96322e`), провенанс «прототип v17», и запрос
  дизайнерам в `figma-fixes.md` завести ступень в коллекции `mode`. Роли закрывают плашки плитки,
  текст «не хватает», строку «Повторить», «· заполнен» и текст счётчиков-пилюль.
- Цена: три значения не из кита 1 — до ответа дизайнеров они живут с провенансом прототипа.
- Альтернатива «одна тёмная плашка `--scrim-dark` на все состояния, цвет несёт только ведущий
  глиф»: прецедент есть (`NavigationTile`), новых ролей нет. Но спека §4 требует «зелёную»,
  «охристую», «серую», «красную» плашки — это отклонение от спеки в `figma-fixes.md`, и текст на
  мягких заливках остаётся нечитаемым.
- Альтернатива «ближайшие существующие: `*-pressed`»: ни одна не проходит 4.5:1 для текста 12px.

### Решение 4 — счётчик-пилюля шага

Прототип: высота 18, 11/16 700, мягкие заливки (`*-surface`) с цветным текстом, пять тонов:
нейтральный, красный, жёлтый, зелёный, серый у замороженного.

- **Рекомендация: своя часть внутри `StepRow`** — геометрия `Badge sm` (высота 16, паддинг 8,
  радиус полный), текст `text-2xs` 12/16 bold, тона на `*-surface` + `*-strong` (решение 3).
- Цена: вторая пилюля в ките рядом с `Badge`; при появлении третьего потребителя её стоит вынести.
- Альтернатива «вариант `soft` у `Badge`»: `Badge` перенесён с мастера Атома `913:8279` с матрицей
  6×2; мягких тонов в мастере нет, и расширение матрицы перенесённого компонента — против правила
  «число вариантов в коде = числу вариантов в мастере».
- Альтернатива «`Badge sm` залитый как есть»: 10/12 на насыщенной заливке с белым текстом — те же
  2.7:1 из решения 3, и строка шага начинает кричать там, где прототип говорит тихо.

### Решение 5 — переполненный шаг: прототип против спеки (вопрос 36)

**Противоречие.** Спека §5: «переполнен — красный счётчик, красная рамка строки», «заполнен —
помета „· заполнен“, строка приглушена». Прототип считает заполненность как `N ≥ max`, поэтому
переполненный шаг получает **оба** вида: красную рамку, «· заполнен» и прозрачность 0.6
([step-over](free-shoot-step-over.png)). Красный на 60% бледнеет — ошибка читается слабее нормы.
Строка причины `.why` в разметке есть, но не заполняется нигде.

- **Рекомендация: переполнен побеждает** — красная рамка и счётчик, без «· заполнен» и без
  прозрачности; приём по-прежнему отклоняется. Это буква спеки §5.
- Цена: расходимся с прототипом, на который смотрят фронты.
- Альтернатива «как в прототипе»: сочетание двух сигналов с противоположным смыслом («готово» и
  «ошибка») в одной строке.

Записано вопросом 36 в `open-questions.md`: противоречие источников — блокер по правилу кита, решается
владельцем.

### Решение 6 — `Progress` компонентом кита

- **Рекомендация:** собрать `Progress` (дорожка, своя доля, чужая доля, «готово») и `ProgressStat`
  на нём; окно автораспределения §12.5 берёт голый `Progress`. Строка долга `Progress` закрывается
  частично — см. 3.3.
- Цена: первый прогресс кита рождается из прототипа одной задачи; если дизайнеры потом нарисуют
  свой, придётся мигрировать.
- Альтернатива «полоса внутри `ProgressStat`, `Progress` не заводить»: окно автораспределения
  соберёт вторую полосу рядом, и в ките будут две реализации одного.

### Решение 7 — кто держит вспышку 1.5 с (§15.3)

- **Рекомендация: компонент.** Проп `flash` — число; смена значения запускает анимацию 1.5 с,
  компонент сам её завершает и сам уважает `prefers-reduced-motion`. Страница только выдаёт новое
  значение (например, `Date.now()`).
- Цена: проп-«спусковой крючок» вместо булева — непривычный API.
- Альтернатива «булев `flash`, страница снимает через таймер» (как в прототипе: класс ставится и
  снимается через 1600 мс): длительность живёт на странице, у каждого потребителя своя, и повторная
  вспышка на том же шаге требует выключить-включить проп.

### Решение 8 — больше восьми миниатюр

Прототип обрезает содержимое шага до 8 (`slice(0,8)`) **без индикации** — девятый кадр в шаге не
виден никак. Спека §9.6: «до 8 штук». В CSS прототипа заготовлен неиспользуемый класс `.slots .plus`
(10.5 `#8A9AAB`).

- **Рекомендация: хвост «+N»** после восьмой миниатюры, `text-2xs` `--muted-foreground`, клик —
  событие `more` (страница решает, что показать: полноэкранный просмотр с первого скрытого).
- Цена: новый элемент, которого в прототипе нет в отрисовке.
- Альтернатива «как в прототипе»: у шага «Общий вид» без максимума кадров может быть 20 — строка
  врёт о содержимом, счётчик говорит 20, миниатюр 8.

### Как устроен перенос «как есть»

- **Разметка.** Постоянные части экрана (шапка, подшапка, тулбар, панель, заголовки этапов и
  повторов, компактная форма, заметки) повторены в шаблоне классами прототипа. Окна (панель
  выделения, поповер назначения, просмотр, окно запуска, сводки) отрисованы **самим прототипом**:
  разметка снята функциями `modal()`, `renderLB()`, `itemHTML()` с обезличенной копии и
  выводится как есть (`app/stands/free-shoot/prototype-data.json`).
- **CSS** — `app/stands/free-shoot/asis.css`, сгенерирован из `<style>` прототипа: каждое правило
  под префиксом `.va` и с хвостом `:not([data-slot] *)`, переменные переименованы в `--va-*`,
  всё в `@layer base`. Обёртка `.va` — `display: contents`, коробку не рисует.
- **Компонент кита внутри перенесённого блока** стоит в `.kit-island`: шрифт и цвет прототипа на
  него не наследуются.

### 11.3. Группы и сверка со `StageSection`

| | Поповер (§10.3), `#btnToStep` | Просмотр (§11.2), `renderLB` |
|---|---|---|
| порядок | «Текущий · <объект>» → каждый неповторяемый этап → «Другие объекты» | «Текущий · <объект>» → «Привязан к · <объект>», если кадр привязан к другому → неповторяемые этапы → «<этап> · повторы» по каждому повторяемому |

| другие объекты | плоским списком, без счёта | по этапам, первым — «Создать «<этап>»», у объекта счёт кадров |

**§11.2 «группируется так же, как поповер» — расширение, не противоречие.** Порядок видов групп тот же;
просмотр добавляет «Привязан к» — без неё перенос (§11.4) не показал бы, где кадр лежит и откуда его
открепить, — и разбивку повторов по этапам с «Создать» — её требует плашка подбора §11.2 («Если объекта
нет — «Создать этап»»). Собрано по прототипу.

**Номера клавиш в группе «Привязан к» не переносятся — доказано кодом прототипа.** Прототип вызывает
`itemHTML(o.id, x, k + 1)` и для этой группы: на скриншоте [viewer-bound](free-shoot-assign-viewer-bound.png)
номера 3, 5–8 при пустом текущем объекте. Но обработчик клавиш прототипа привязывает цифру только к
шагу текущего объекта (`stageById[O(state.cur).stageId].steps[+e.key-1]`), а без текущего отвечает
«Сначала выберите текущий объект» (§16.2). Номер в чужой группе указывает на клавишу, которая делает
другое. Кит следует §16.3: номера только в группе текущего. Строка — `figma-fixes.md`.

**Одна роль или две — две.** В поповере группа — подпись над пунктами: роль мастера `ListGroup`
`542:4969`, в ките `SelectGroup` (13 medium, линия между группами такта 21). В просмотре группа
сворачивается, и у прототипа её свёрнутость и свёрнутость этапа панели — одно состояние: `state.closed`
по id этапа, свернул «Общие данные» в просмотре — свернулся этап в панели
([viewer-collapsed](free-shoot-assign-viewer-collapsed.png)). Это роль `StageSection` такта 32:
липкий заголовок-переключатель, счёт, метка «повторяемый» — все части уже есть. `SelectGroup`
сворачивания не имеет, добавить — расширение матрицы перенесённого мастера. Общее состояние свёртки —
логика страницы: на `/free-shoot` список просмотра и панель читают один `closedStages`.

### 12.2. Сверка с `Lightbox` кита

| | `Lightbox` (композиция Атома `8867:69956`, светлая) | Просмотр прототипа |
|---|---|---|
| поверхность | `--dialog` — светлая (`bg/page`); тёмная композиция `8887:63887` не переносилась: тёмная тема — отдельная задача | тёмный слой 95% |
| верхняя полоса | 56: счётчик `Badge` «N из M» слева, слот действий по центру, крестик `IconButton` 40 справа | позиция, имя файла и метка — слева, крестик 32 справа |
| кадр | область между полосами, паддинг 48, содержимое — слот | кадр с плашкой под ним и кольцом |
| стрелки | `ButtonArrow` 48 у краёв окна, гаснут на границах | 44×64, не гаснут |
| нижняя полоса | подпись 16/20 | нет |
| **боковая панель** | **нет** | 340: метаданные и список шагов |
| поведение | `Dialog` Reka: модальность, ловушка фокуса, Esc, возврат фокуса | Esc — своим обработчиком страницы |

**Роль совпадает.** Подпись композиции Атома — «Полноэкранный режим просмотра фото и видео»; §11.1 —
то же. Кадр с плашкой ложится в слот кадра (композиция внутри слота, матрица не меняется), имя файла и
метка — в слот действий. Не ложится одно — **боковая панель**: у `Lightbox` её нет, и снаружи её не
приставить: `Lightbox` — модальный `Dialog` с ловушкой фокуса, всё вне его содержимого недоступно с
клавиатуры и мышью. Панель — только слотом внутри, то есть **расширение матрицы перенесённого
компонента — решение 1**.

Если просмотр встаёт на `Lightbox`, он становится светлым: тёмный вид — оформление легаси, у кита
перенесена светлая композиция. Стрелки гаснут на границах — поведение `Lightbox`, прототип их не
гасит.

### 12.3. Ширина боковой панели

**Замер.** Каждая подпись источника подставлена в пункты `AssignOption` на `/free-shoot` (панель 340,

| она же — заморожен, хвост «замок + 3 / от 2» | 40 |
| она же — привязано до вас, хвост «замок» | 24 |
| она же — доступен, хвост «0» | 27 |
| «проверен и закрыт — добавить нельзя» — подпись замороженного | 3 |

держатель галочки слева и «Открепить» справа.

Ни 418, ни округление до сетки 4 (420) из правила кита не выводятся: у кита нет ступени ширины боковой
панели. Ближайшая опора — **440, ширина панели структуры того же экрана** (`.pane.right` прототипа,
такт 30), где лежит тот же список этапов и шагов. Это прецедент экрана, а не правило кита, — поэтому
**решение 2**. Цена 440 против 340 у кадра: при 1440 область кадра 1000 вместо 1100, кадр 62vw = 893
помещается; при 1280 — 840, кадр подстраивается под область.

замороженного пункта — «Инвентарный или учётный ном…». Порция 2 закрыта, строка — для будущей правки
ширины поповера.

### 12.9. Решения — стоп-точка

**Решений владельцу: 3.** Ещё 10 развилок закрыты фактом, прецедентом или правилом — таблица ниже.

#### Решение 1 — каркас: `Lightbox` со слотом боковой панели

- **Рекомендация: `Lightbox` кита + слот `aside` справа во всю высоту** (расширение матрицы — строка в
  `waves.md`). Кадр с плашкой — `FrameStage` + `FrameBindBar` в слоте кадра, имя файла и метка — в слоте
  действий, панель — метаданные и список такта 33. Роль совпадает («полноэкранный режим просмотра»),
  поведение `Dialog` — модальность, фокус, Esc — приходит готовым.
- Цена: просмотр становится **светлым** — тёмный вид легаси не переносится; стрелки гаснут на границах;
  имя файла встаёт по центру полосы, а не слева; у `Lightbox` появляется слот, которого в композиции
  Атома нет, — при синке это вопрос дизайнерам.
- Альтернатива «свой каркас на частях кита» (`Dialog`, `Badge`, `IconButton`, `ButtonArrow`): второй
  полноэкранный просмотр рядом с `Lightbox` — две реализации одной роли. Тёмный вид к тому же требует
  тёмных ролей, которых в теме нет, — отдельное решение.
- Альтернатива «боковая панель отдельным слоем поверх `Lightbox`»: ловушка фокуса `Dialog` отрезает её
  от клавиатуры и мыши — не работает.

#### Решение 2 — ширина боковой панели

- **Рекомендация: 440** — ширина панели структуры того же экрана, где лежит тот же список; с запасом 22
  к замеренному минимуму 418.
- Цена: область кадра уже на 100 (при 1440 — 1000 вместо 1100); кадр подстраивается.
- Альтернатива «420» — замеренный минимум, округлённый до сетки 4: без запаса, первое же название длиннее
  «Поэтажных планов» обрежется.

**Открытие на группе.** Обработчик прототипа: `openObjForm`, затем поиск `.fgrp` с текстом группы,
`scrollIntoView({ block: 'start' })` и фокус на первое поле строки под заголовком. Замер: фокус — на
«Состояние» (`data-k="cond"`); при 1440×900 окно помещается и не прокручивается, при 1280×720 прокрутка 144 —
до упора, группа поднимается насколько позволяет высота.

**Граница.** Страница решает, на какой группе открыть: берёт группу из события `edit(group)` `RepeatForm` и
хранит её в UI-состоянии вместе с открытым повтором. Окно исполняет: группа с признаком `autofocus` при
монтировании прокручивает **тело** окна к себе и ставит фокус на первый контрол. Без группы фокус — по
поведению `ModalCard` (Reka: первый фокусируемый — крестик шапки), у прототипа фокуса нет вовсе. Ловушка (`reka-ui` `FocusScope.js`, стр. 137)
фокуса Reka не перебивает: `FocusScope` ставит свой фокус, только если фокус ещё не внутри окна.

### 14.4. Зависимые поля (§14.4)

У прототипа строка зависимого поля всегда в разметке и прячется `display: none`; `sync()` на каждом `input` и
`change` сверяет значение родителя с `dep.v`. Замер: смена двух родителей показывает обе строки, окно
растёт с 778 до 869, фокус остаётся на месте ([до](free-shoot-form-dep-before.png) / [после](free-shoot-form-dep-after.png)).

**Граница — по заданию.** Связь — данные формы этапа (`dep: { k, v }`); видимость считает страница реактивно
от значения родителя, строка выводится `v-if`. В компонент входит только вид поля. Значение скрытого поля
прототип сохраняет как есть (читает все `[data-k]`, скрытые тоже) — поведение страницы, в компонент не входит.

### 14.5. Обязательные поля и проверка при сохранении (§14.6)

| Что | Прототип | Спека |
|---|---|---|
| знак обязательности | « *» `#D9534F` 700 после подписи | — |
| когда проверяется | только по «Сохранить» (и «Создать») | §14.6 «при сохранении» |
| что выводится | уведомление `toast('Заполните: …', 'err')`: 280.8 × 40.8, внизу слева в 20 от края, заливка `#8E332F`, текст 13 белый; окно остаётся открытым | §14.6 «перечисление: „Заполните: список подписей“»; §18 `form.required` — раздел «Отказы» |
| вид поля | **не меняется**: рамка пустого обязательного поля та же `#E1E7EF` | — |
| список | подписи незаполненных обязательных через запятую; в данных обеих форм обязательное по одному полю — список из одной подписи | `form.required` |

Спека и прототип согласны: отказ-уведомление, поля без ошибки. Кит даёт больше: у `Input` есть состояние ошибки
(`invalid`, мастер Атома), у `Field` — `invalid`, красящий подсказку (мастер кита 1: красные рамка и
подсказка). Спека §14.1 уже красит пустое обязательное поле цветом ошибки — в компактной форме. У `Toast`
кита тона ошибки нет: `Alert` (мастер `Notification` `5883:58974`) знает виды `default` и `timer`, угол показа —
долг (правый нижний). Где выводить отказ и красить ли поле — **решение 2**.

### 14.6. Источник значения (§14.2) и подсказки (§14.5)

- **Источник «распознано» / «по умолчанию» в окне не выводится** — строки `.f-row` его не знают, `autoSrc`
  читает только `formPreview`. §14.2 описывает компактную форму. Закрыто фактом: в окне источника нет.
- Подсказки из распознанного — вне порции. Для следующего такта: прототип выводит их и в окне редактирования,
  если в ленте есть выделение (`ids` не передан — берётся текущее выделение), не только при создании.

### 14.8. Черновик API

```vue
<!-- Страница: окно открыто событием edit(group) у RepeatForm; группа — UI-состояние -->
<ModalCard v-model:open="formOpen">
  <ModalCardContent>                                   <!-- center md 600 -->
    <ModalCardHeader :title="`Форма · ${stage.title}`" subtitle="Динамическая форма повторяемого этапа" />
    <ModalCardBody class="flex flex-col">
      <FieldSet v-for="g in groups" :key="g.title" :legend="g.title" :autofocus="g.title === formGroup">
        <template v-for="f in g.fields" :key="f.k">
          <Field v-if="visible(f)" orientation="left" label-width="form" :label="f.l" :required="f.req" :invalid="errors.has(f.k)">
            <Select v-if="f.opts" v-model="draft[f.k]" :items="withEmpty(f.opts)" :show-icon="false" placeholder="—" />
            <Input v-else v-model="draft[f.k]" :invalid="errors.has(f.k)" :show-icon="false" placeholder="" />
          </Field>
        </template>
      </FieldSet>
    </ModalCardBody>
    <ModalCardFooter>
      <Button variant="secondary" @click="formOpen = false">Отмена</Button>
      <Button @click="save()">Сохранить</Button>              <!-- проверка §14.6 и form.required — страница -->
    </ModalCardFooter>
  </ModalCardContent>
</ModalCard>
```

| Компонент | Что новое | Пропсы | События |
|---|---|---|---|
| `Field` (`ui/field/`) | при решении 1: колонка подписи и знак обязательности | `labelWidth?: 'content' \| 'form'` — только `orientation="left"`, `content` по умолчанию (мастер), `form` — 170; `required?: boolean` — « *» `--destructive` после подписи | — |
| `FieldSet` (`ui/field/`, новый) | группа полей формы: `<fieldset>` с `<legend>`, линия над второй и далее, строки через 8 | `legend?: string`, `autofocus?: boolean` — прокрутить тело к группе и поставить фокус на первый контрол при монтировании | — |

Имя `FieldSet` — каноническое у shadcn-vue (семейство `Field`: `FieldSet`, `FieldLegend`, `FieldGroup`);
легенда — пропом, как `label` у `Field`. Группа без заголовка (этап «Здание / цех») — `FieldSet` без `legend`.

**Тексты §18, которые компоненты выводят сами:** нет. « *» — знак, не текст. Страница выводит `form.saved`
«Форма сохранена» и `form.required` «Заполните: <список полей>»; шапку и кнопки — тексты прототипа (в §18 их нет):
«Форма · <этап>», «Новый повтор · <этап>», «Динамическая форма повторяемого этапа», «Отмена», «Сохранить»,
«Создать».

**Граница компонента и страницы** (дополнение к разделу 4):

| Что | Чьё | Как |
|---|---|---|
| открыть окно, на какой группе | страница | событие `edit(group?)` `RepeatForm` → UI-состояние `formOpen`, `formGroup` |

### 14.9. Решения — стоп-точка

**Решений владельцу: 2.** Ещё 9 развилок закрыты фактом, правилом или прецедентом — таблица ниже.

#### Решение 1 — строка формы «подпись 170 — поле»: расширение `Field`

- **Рекомендация: `Field orientation="left"` + два пропа** — `labelWidth="form"` (колонка 170, новый токен
  `--container-form-label`, провенанс — прототип `.f-row`) и `required` (« *» `--destructive`, прецедент
  `StepRow` такта 30). Подпись остаётся подписью мастера — 15/20 Bold `--foreground`; по замеру 14.2 все
  подписи обеих форм ложатся в 170 не больше чем в две строки, то есть в высоту поля 40. Высота окна
  «Единица оборудования» по расчёту — около 830 при 11 строках (ModalCard 32 + шапка 52 + 24 + тело 626 + 24 +
  подвал 40 + 32): при 1440×900 тело прокручивается на ~40, при 1280×720 — на ~200.
- Цена: расширение матрицы перенесённого мастера `720:11753` двумя осями, которых у кита 1 нет, — запрос
  дизайнерам в `figma-fixes.md`; подписи 15/20 Bold тяжелее легаси 13 regular, три из 13 строк — в две строки.
- Альтернатива **«колонка 224»**: все подписи «Единицы оборудования» в одну строку (самая длинная со знаком —
  222); поле 304; «Причина, по которой доступ не обеспечен» у здания — по-прежнему две строки. Провенанса у 224
  нет — только замер.
- Альтернатива **«`Field` сверху»** (`orientation="top"`, без расширения): как вкладка «Форма осмотра» (№ 42).
  Цена — строка 68 вместо 40: тело около 930, окно прокручивается при любом экране; раскладка расходится с
  легаси. Знак обязательности всё равно нужен — расширение на одну ось остаётся.
- Альтернатива **«новая часть `FormRow`»** вместо расширения: вторая реализация подписи поля рядом с `Field` —
  прецедент такта 34 против двух реализаций одной роли.

#### Решение 2 — проверка при сохранении: где отказ и красить ли поле

- **Рекомендация: уведомление `Toast` с `form.required` «Заполните: <список>» — как прототип и §18 — плюс
  состояние ошибки у пустых обязательных полей** (`Input invalid` + `Field invalid`), снимается, когда поле
  заполнено. Довод за ошибку поля: в окне с прокруткой поле может быть вне видимой области, уведомление
  исчезает через 5 с; спека сама красит незаполненное обязательное цветом ошибки в компактной форме (§14.1).
  Текста у ошибки поля нет — в §18 его нет, `errorText` пустой.
- Цена: у кита нет тона ошибки у уведомления — `Toast` выйдет нейтральным (у легаси — тёмно-красным) и в правом
  нижнем углу (у легаси — в левом): оба — долг `Toast`. Ошибка поля — сверх легаси и сверх буквы §14.6.
- Альтернатива **«только уведомление»** — буква прототипа и спеки; поле не подсвечивается.
- Альтернатива **«сводка в окне»** — «Заполните: …» строкой внутри окна (`ModalCardText` цветом ошибки
  или слот `note` подвала): источника нет ни у прототипа, ни у спеки; новая подача текста отказа.
