# Доски решений

Доска решений — HTML-страница, на которой владелец выбирает вариант глазами там, где сомневается: карточки вариантов со снимками и живыми
ссылками на стенд, рекомендация, ✓ / ✕ по разделу, заметки. Основа — скилл владельца «Доска решений» (подход «Канвас
решений»); здесь он в редакции для приёмки экранов на ките. Правило — `docs/orchestrator.md`, раздел 9, пункт 12
(владелец, 2026-10-09, такт 95).

## Когда доска

Доска — для мест, где у владельца сомнение. Собирается по его слову: «на доску» у пункта маршрута или замечания.

Сессия доску без этого слова не строит. Где она видит два и больше жизнеспособных варианта вида или компоновки
(пересмотр вкусового решения, пакет предложений ревью, карточка правила 23г с изменением вида), она ставит пометку
«доска?» и одну строку — между чем выбор. Дальше решает владелец: доска или ответ текстом по разделу 9, пункт 2.

Доска лишняя, когда решение одно (хватит снимка «после»), правка текстовая, дефект или вопрос по репо.

## Кто собирает

- Варианты, которым нужен код, собирает сборщик тактом доски. Каждый вариант живёт на стенде за оснасткой
  `?variant=<id>` (строка в `docs/naming.md`), снимки снимаются с тех же адресов. Код вариантов временный.
- Доску без кода — снимки текущих состояний, вайрфреймы — пишет сессия приёмки сама.
- После решения следующий такт оставляет выбранный вариант, убирает остальные и оснастку `?variant=`. Строка реестра
  ссылается на доску.

## Файлы

- `docs/boards/<id>/index.html` — копия `template.html`. Меняются только `<title>` и JSON внутри
  `<script type="application/json" id="board">`; CSS и JS остаются как в шаблоне.
- `docs/boards/<id>/img/` — снимки. Область интерфейса 1:1 на 1440 × 900, мелкие детали — ×2; PNG или JPEG до ~300 КБ.
  Лупа доски открывает снимок целиком.
- `id` — `<цель>-<тема>-v<N>`: латиница, цифры, `-`. Новая итерация — новый `v`, папка прежней остаётся.
- Данные на снимках — демо-данные стенда: репо публичное.

## Схема BOARD

- `id`, `stage` («Приёмка»), `task` (цель: `scheme-edit`, `tariffs`), `title`, `lead` — что выбираем, одна-две фразы.
- `scope` — граница доски одной строкой.
- `sources` — `[{label, note?, href?}]`: раздел рабочего документа, строка реестра, номер замечания.
- `caveat` — `{title, items[]}`: чего сессия не знает и просит проверить.
- `principles` — строки-принципы, которые держит решение.
- `flow` — `[{t, sub?}]`: карта шагов, если выбор касается флоу.
- `sections` — `[{id, tag?, title, purpose?, decide?, synthTitle?, synth[], cards[]}]`. `decide: "pick"` — раздел
  выбора одного варианта; довод за рекомендацию — `synth` с `synthTitle: "Почему предлагаю A"`. Под каждым разделом
  шаблон сам ставит ✓ / ✕ и поле «Что поправить».

Карточки (`kind`):

- `variant` — `{id, title: "A · …", frame: "web", img | wf, href, caption?, plus, minus, suggest?: true}`. `href` — живой
  адрес варианта на стенде, `http://localhost:3000/…?variant=a`; название карточки становится ссылкой. Рекомендованный
  вариант — `suggest: true`.
- `pair` — `{id, title, before, after, diff[], suggest?: "accept"}` — «было / стало», по просьбе владельца.
- `screen` — `{id, title, state?, frame: "web", img | wf, caption?, suggest?: "keep"}` — состояние без выбора варианта;
  вердикт «оставить / поправить / убрать».

Вайрфрейм `wf` у `frame: "web"` — `{side?, main, aside?}`, каждая колонка — массив блоков:

- `{bar: "Заголовок", actions: ["Создать"]}` — шапка;
- `{h: "…"}`, `{p: "…"}` — заголовок, текст;
- `{btn: "…", primary: true}`, `{btn: "…", ghost: true}` — кнопки;
- `{ph: "что здесь", h: 120}` — заштрихованная заглушка;
- `{tabs: [...], on: 0}`, `{seg: [...], on: 0}`, `{chips: [...], on: 0}`, `{nav: [...], on: 0}`;
- `{kv: [["ключ", "значение"]]}`, `{field: "Подпись", value: "…"}`, `{list: [...]}`;
- `{table: {cols: [...], rows: [[...]]}}`;
- `{row: [[блоки], [блоки]], w: [1, 2]}` — колонки;
- `{note: "…"}` — пометка сессии на экране;
- `{img: "img/…"}`, `{hr: true}`.

Текст — от первого лица, коротко, утвердительно; `**жирный**` работает. Ссылки — `http://` или `https://`.

## Как владелец смотрит и отвечает

Сессия даёт путь `C:\GitHub\ro-admin-ds\docs\boards\<id>\index.html` и ссылку
`file:///C:/GitHub/ro-admin-ds/docs/boards/<id>/index.html`. Владелец открывает доску в браузере, выбирает вариант или
ставит ✓ у раздела (✓ принимает рекомендацию), пишет правки в «Что поправить» или в заметке к карточке, нажимает
«Скопировать решения» и вставляет текст в сессию. Отметки живут во вкладке до её закрытия.

## Как читать решения

Текст кнопки начинается строкой «РЕШЕНИЯ ПО ДОСКЕ · <title> · <id>». Дальше по разделам: ✓ принят, ✕ не то или без
решения; «Что поправить»; у раздела выбора — «Вариант: <id> — выбрано» или «принято с разделом»; вердикты и заметки
карточек.

- Выбранный вариант идёт в промпт блоком «РЕШЕНИЯ ВЛАДЕЛЬЦА» с id доски; провенанс строки реестра — «владелец, дата,
  доска <id>».
- Заметка у выбранного варианта — ТЗ к доработке.
- ✕ у раздела — «Что поправить» становится входом итерации `v<N+1>`.
- Раздел без решения — один вопрос владельцу списком.
