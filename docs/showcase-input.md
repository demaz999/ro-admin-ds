# Гайд «Поле ввода»

Все содержательные правила, объяснения и тексты сравнений хранятся в
`app/components/showcase/input-guide.ts`. Страница
`app/pages/components/input.vue` отвечает только за компоновку, реактивное состояние и
живые примеры. Это единственный ручной источник текста гайда для витрины и агентов.

Фактический API не переписывается в отдельную таблицу. Размеры, варианты и пропы Input
проверяются по `app/components/ui/input/index.ts` и
`app/components/ui/input/Input.vue`; обвязка — по
`app/components/ui/field/index.ts` и `app/components/ui/field/Field.vue`. Канон имён и
сборки — `docs/naming.md`, источники и роли токенов — `docs/tokens.md`.

Структура объяснения и правила применения адаптированы по гайду Контура «Поле ввода»,
доступному 2026-09-15. Решение владельца: перенести смысл правил, не копируя визуал и
значения Контура. Композиция и форма подачи — решение «конвейер 2».

## Карта покрытия референса

| Правило референса | Результат | Место или request ID | Причина |
|---|---|---|---|
| Короткий текст и числа без предсказуемого формата вводятся в Input | перенесено | `#purpose` | Совпадает с назначением текущего компонента. |
| Текст длиннее пяти слов, выбор, дата и время требуют другого контрола | адаптировано | `#purpose` | Названы доступные в ките Textarea, Select, Autocomplete и пикеры без копирования каталога референса. |
| Предсказуемый формат требует маски или специального поля | требует реализации | `SHOWCASE-INPUT-001` | Текущий Input поддерживает только обычный `type=text`. |
| Выбирать нативный тип поля по данным | адаптировано | `#purpose`, `#code`, `SHOWCASE-INPUT-003` | Нативный тип и штатные атрибуты пока нельзя передать через API. |
| Название — существительное с заглавной буквы, без двоеточия, «ваш» и «введите» | перенесено | `#label`, пара «правильно / неправильно» | Правило не зависит от визуального языка. |
| Плейсхолдер нужен только когда названия недостаточно | адаптировано | `#behavior` | В текущем Input он одновременно становится плавающей подписью. |
| Плейсхолдер светлеет при фокусе и исчезает после ввода | противоречие | `#behavior` | Фактически `isFloating = focused || value`: текст переходит вверх и остаётся видимым. |
| Конкретный пример значения лучше предзаполнить, чем показать плейсхолдером | перенесено | `#behavior`, пара «правильно / неправильно» | Живой пример показывает редактируемое `model-value`. |
| Формат и ограничения нельзя прятать в плейсхолдере | адаптировано | `#behavior`, `SHOWCASE-INPUT-001` | Постоянную подсказку даёт Field; форматированного Input пока нет. |
| Плейсхолдер не заменяет название; исключение — компактное одиночное поле или уточнение в группе | адаптировано | `#behavior` | На странице Field сохраняет внешнее название; прямой Input допустим для самостоятельного поиска. |
| Вычисляемое значение оформляется автоматическим полем | неприменимо | — | В текущем ките нет AutoField, а доменный паттерн выходит за рамки гайда Input. |
| Очистка нужна при частой замене значения и выключена по умолчанию | перенесено | `#behavior` | `clearable` включается явно. |
| Очистка заменяет правую прикладную иконку | адаптировано | `#behavior` | У текущего Input нет слота правой прикладной иконки: опциональная иконка слева, очистка справа. |
| Очистка видна только при наличии значения | противоречие | `SHOWCASE-INPUT-005` | Реальное условие `clearable && isFloating` показывает кнопку и в пустом поле под фокусом. |
| В одном поле очистка видна постоянно, в группе — по hover/focus | требует реализации | `SHOWCASE-INPUT-006` | API не различает одиночный и групповой контекст. |
| Клик по очистке стирает значение и возвращает фокус в поле | адаптировано | `SHOWCASE-INPUT-004`, живой пример `#behavior` | Очистка model реализована, гарантия возврата фокуса — нет. |
| Иконка очистки темнеет по hover, область клика равна высоте поля | требует реализации | `SHOWCASE-INPUT-006` | У текущей кнопки фиксированный размер и нет выраженного hover-состояния. |
| Счётчик стоит в строке вводимого текста | требует реализации | `SHOWCASE-INPUT-007` | Field выводит counter справа в отдельной строке под контролом. |
| Размер поля выбирается по роли; ведущий контрол крупнее | адаптировано | `#variants`, `#layout` | Вместо шкалы референса показаны фактические `md` и `lg` кита. |
| Подпись слева выровнена по базовой линии первой строки | требует реализации | `SHOWCASE-INPUT-002` | Field центрирует label по высоте контрола, включая многострочное название. |
| Ширина соответствует ожидаемой длине; в форме не больше четырёх ширин | перенесено | `#layout`, пара «правильно / неправильно» | Правило показано живыми Input без новых возможностей кита. |
| Фокус по клику и Tab выглядит одинаково | перенесено | `#keyboard` | Проверяется на живой паре полей. |
| Фокус ошибочного поля не должен скрывать ошибку | адаптировано | `#variants`, `#keyboard` | `invalid` управляется внешним состоянием и остаётся видимым при фокусе. |
| Enter может переходить дальше, кроме последнего поля | адаптировано | `#keyboard` | Это поведение формы; сам Input фокус не переключает. |
| Ошибка обозначается красной рамкой | адаптировано | `#variants` | Кит использует собственные токены поверхности и текста ошибки, а не рамку референса. |
| Точные размеры, цвета и визуальная кастомизация референса | неприменимо | — | Визуал определяется компонентами и токенами Рососмотра/Atom. |

Открытые расхождения `SHOWCASE-INPUT-001`–`SHOWCASE-INPUT-007` находятся в
`docs/showcase-requests.md`. На странице они описаны как ограничения, а не как
доступные возможности.
